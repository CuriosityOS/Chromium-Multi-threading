## Remaining blockers / deliberate exclusions

- **Do not mechanically TLS `MemoryCache`** (`platform/loader/fetch/memory_cache.cc:135,195-224`): singleton owns Oilpan data, main task runner, registrations, and a shared dump provider. Generic ResourceFetcher has main-thread guards, but ImageLoader and stylesheet-resource paths also call it directly. ImageResource itself still has main-thread CHECKs. Enabling replica image/resource loading needs a separate ownership/task-runner design; the image-singleton proposals do not fix that.
- **Live platform/theme settings**: `core/layout/layout_theme.cc:177-192` selection colors and singleton focus-ring state; Linux font system-family/render settings and scrollbar-theme state need synchronized snapshots or publication of updates, not independent stale TLS defaults. Startup-only settings are not assumed to race unless runtime setters can execute concurrently.
- Main-only font prewarming has shared mutable dedup flags/sets (`FontCache::PrewarmFamily`, `MaybePreloadSystemFonts`, input/textarea first-prewarm flags). Keep prewarming off the replica or route it to its owner; TLS alone cannot make the prewarmer client callable on arbitrary threads.
- Skipped the four explicitly already-fixed globals, existing per-thread Persistent conversions, tests, devtools-only paths (including PaintTimelineReporter / selector-statistics maps), and non-Linux-only implementations. Ordinary-page/widget pausers/input state remain conditional on those subsystems being used; nonordinary Page alone does not establish reachability.
- Not reported as mutable races: initialized-once read-only media-query function table (assuming normal CoreInitializer-before-worker startup); immutable TimeClamper; the unmodified returned-by-value SavedLayerScrollOffset default; ToBlinkStringFast's numeric cache (worker calls bypass it); immutable/thread-safe-refcounted timing-function presets. `DEFINE_THREAD_SAFE_STATIC_LOCAL` only disables its access DCHECK; it does **not** synchronize mutable contents.
- Per-thread caches retain existing cache semantics (including context-dependent CSS exposure caching); this is not a redesign of per-Document feature filtering. Leaky TLS caches increase per-thread retained memory and require shutdown/LSan coverage. Owner-thread confinement of all live DOM/layout/Oilpan objects remains mandatory.

Checked [C++ TLS and static initialization](https://en.cppreference.com/w/cpp/language/storage_duration.html), [atomic fetch_add](https://en.cppreference.com/cpp/atomic/atomic/fetch_add), [Chromium Mojo sequence-affinity docs](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/mojo/public/cpp/bindings/README.md), and [scoped_refptr::release](https://chromium.googlesource.com/chromium/src/+/HEAD/base/memory/scoped_refptr.h); verified API fit against the current remote checkout and existing per-thread macro. Compared shared locking/completed-once immutable initialization against per-thread state, and shared atomics against TLS. Chose the smallest owner-thread isolation changes for reference-returning caches and scope policy, atomic allocation for globally unique IDs, and main-thread guards for explicitly main-only metrics. No dependency added; KISS/DRY, no synchronization-framework rewrite.
